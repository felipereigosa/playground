## Claude

I read the shelf code (`menu.js`, `world.js`) and BrickFusion (`Lego` class, `parts.glb`, giant floor-standing bricks). I'd use one rule for both cases: **the icon is a representative of the gadget, and the gadget owns loose parts that are never in the icon.**

## The mechanics

- **Taking out:** you pull the icon and let go, as now. When it finishes growing, the gadget deploys its parts relative to where you let go and which way you were facing.
- **Icon stays clean:** the shelf copy is only the model named in the registry (the gun alone, a single brick). Parts only exist after deploying.
- **Putting away:** with the menu open, grabbing *any* part of the set gathers the whole set. The parts fly into your hand and merge into the icon, which you drop on the shelf. This extends the rule you already have, where grabbing a world gadget with the menu open shrinks it to an icon.
- **No special handle:** nothing has to be the "master" object, so the Lego case needs no box or particular brick to find.

## Gun and targets

I'd make the targets their own gadget rather than something the gun brings along.

- **Why separate:** the bow, thrown balls and splash paint on your list will all want something to hit, and sometimes you'll want the gun without a range.
- **Targets gadget:** the icon is one target. Letting it go deploys a handful 3 to 8 m ahead of where you faced.
- **Reacting to shots:** a new optional `hit(point, direction, by)` on gadget modules, which the blaster's bolts call on whatever they strike. Targets spin, fall or shatter, and other gadgets can ignore it or react later.

If you'd rather they come with the gun, the same mechanism covers it (targets as the gun's owned parts). The cost is that you can't have one without the other.

## Lego

- **Taking out:** the icon is a brick. Letting it go pours the set onto the floor in front of you.
- **While out:** each brick is an owned part, so grabs go to the Lego module, which keeps BrickFusion's snap and detach logic.
- **Putting away:** open the menu, grab any brick or the build, and everything gathers into the brick icon.

## What it costs in code

It is a small change:

- Loose parts get the same `userData.gadget` tag the root has, so `gadgetOf` already routes their grabs.
- An instance gets a `parts` list.
- Modules get a `deploy(position, facing)` call when growing ends.
- `world.js` gets a gather animation for parts on shrink.
